# 安全反馈 / Security reporting

不要在公开 issue、PR、附件或评论中贴出真实用户消息、心理档案、令牌、数据库地址或可复用的攻击凭证。请通过仓库提供的私密安全报告渠道联系维护者；若尚未配置，应先请求一个私密渠道，再提供敏感细节。

Do not put real user messages, psychological records, tokens, database addresses, or reusable attack credentials in public issues, PRs, attachments, or comments. Use the repository's private security-reporting channel. If none is configured, first request a private channel before sharing sensitive details.

请优先使用完全虚构的最小复现，提供受影响版本、触发条件、预期和实际结果；不要附带生产数据转储。当前是首个独立候选版本，没有承诺长期支持或响应时限。

Prefer a minimal reproduction with entirely fictional data, including the affected version, trigger, expected result, and actual result. Do not attach production dumps. This is the first standalone candidate; no long-term support or response-time commitment is made.
