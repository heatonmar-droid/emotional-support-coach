# 情绪支持与心理教练：这个开源后端能用来做什么

[English](INTRODUCTION.en.md) · [项目首页](../README.md) · [参与共创](../CONTRIBUTING.md)

同样是聊工作压力，有人只想把今天的烦心事说完，有人已经来回想了几天，希望有人帮忙把问题理清楚。聊天系统如果始终采用同一种回应方式，就容易在不该给建议时给建议，在需要具体帮助时继续追问。

Emotional Support Coach 把日常支持和心理教练做成了两种可以切换的对话模式。它提供文字后端、提示词和记忆处理代码，开发者可以接自己的小程序或网页，也可以只拿其中一部分做实验。代码采用 MIT 许可。

这篇文章介绍的是目前仓库实际提供的能力。下面的场景都是虚构示例，描述设计意图，不是用户记录、真实模型输出或效果证明。

## 两种模式，区别在对话节奏

日常支持偏向倾听和自然交流。它的提示词要求根据上下文判断这一轮需要什么，不机械地重复「共情、提问、建议」，也不要求每次回答都以问题结尾。

心理教练更关注已有信息是否足够。如果还缺关键事实，就问一个必要的问题；如果信息已经够用，就尝试整理、区分选择，或者提出一个可以撤回的小尝试。用户不想推进时，也应该停下来。这里的「教练」是一种对话方式，不代表执业资格或治疗服务。

| 虚构情境 | 日常支持可以侧重什么 | 心理教练可以侧重什么 |
|---|---|---|
| 「今天开会被打断好几次，我不想分析，先让我吐槽。」 | 听清委屈，尊重暂时不分析的要求 | 同样尊重倾诉，不强塞行动计划 |
| 「我已经说了很多遍了，现在想知道明天怎么跟同事谈。」 | 顺着当前诉求转向具体讨论 | 整理事实、表达边界，准备一段可修改的说法 |
| 「任务越堆越多，我连文档都不想打开。」 | 理解压力来自哪里，避免催促 | 在信息足够时，把第一步缩小到能开始的动作 |

模式切换不会取消安全判断，也不会自动让某种方法适合所有人。输出仍取决于模型、提示词和当轮上下文，需要用具体案例验证。

## 哪些项目适合从这里开始

**小程序或网页中的情绪支持聊天。** 如果你已有界面，需要一个能处理对话上下文、账号隔离和回复结果的服务，可以接这里的 API。仓库有独立账号令牌适配层，但没有附带完整的注册登录平台、支付或运营后台。

**围绕压力、关系或行动整理的对话原型。** 可以让使用者选择偏倾听的模式，或偏整理的模式，再观察这种区别是否符合产品需求。不需要为了切换语气复制整套存储系统，两种模式共享上下文和记忆机制。

**提示词与记忆机制研究。** 主提示词和共享规则放在独立文件里，便于修改。你可以用一组从头编写的虚构对话检查：模型是否连续追问、是否把猜测记成事实、用户纠正后是否还沿用旧信息。仓库里的离线测试可以作为起点。

**方法卡检索实验。** 如果你想研究给模型提供少量相关参考是否有帮助，可以导入随包方法卡，再比较有无检索时的表现。检索命中不等于方法合适，也不能只凭模型引用了一张卡就认定回答更好。

## 一轮对话怎样完成

请求进入后，服务器先验证账号令牌，再读取该账号的模式、会话上下文和相关记忆。请求里自填一个用户 ID 不能替代认证。方法卡已导入时，系统也会检索相关参考。

安全判断和普通回复草稿并行运行，随后根据安全结果选择回复路径。最终内容需要通过结构校验，并成功保存，接口才发出完成事件。长度截断只进行一次有上限的重试，不无限请求模型，也不把残缺的助手回复当成正常结果保存。

前端通过 SSE 接收进度和结果。当前协议在回复完整生成后发送正文，**不是逐 token 输出**。接入时应等待 `workflow_end`，错误则处理 `error`；仅看到 HTTP 200 不能认定这轮成功。

回复后的记忆提取在后台执行。更完整的流程和当前限制见 [架构说明](ARCHITECTURE.md)。

## 记忆分成几部分，各自解决不同问题

近期上下文用于接上刚才的话，但有条数和字符预算，不会把无限历史全部塞进模型。

长期画像保存在 PostgreSQL 中，用来保留跨会话可能有用的信息。事件记忆使用 Mem0 OSS 和 Qdrant，按当前话题检索相关事件。模型提出的记忆写入需要核对用户原句；纠正和遗忘操作也受到账号与记录范围约束。

例如，在虚构测试里，用户先说「我正在准备换工作」，后来明确纠正「我已经决定暂时留下」。需要检查的是旧信息是否失效、后续回答是否使用新信息，而不是仅仅检查数据库有没有多一条记录。

记住更多并不一定更好。提示词把记忆当作参考，不要求每轮提起往事，也不能因为有一条旧记忆就把用户拉回不想讨论的话题。

还要区分「不再用于回答」和「物理删除」。自然语言遗忘可能只是使画像条目失效，原聊天记录仍存在；清空接口也不承诺删除供应商保留数据、备份或 Mem0 操作历史。具体范围见 [隐私说明](PRIVACY.md)。

## 68 张方法卡怎样使用

随包卡片包含适用情境、目的、引导步骤和停止边界，涉及当下稳定、与念头拉开距离、价值澄清、小步行动及人际表达等方向。正文保留中文。

数据库初始为空，配置自己的 embedding 服务并导入卡片后才会参与检索。系统依据当前问题和近期上下文寻找相关内容，主回复模型再决定是否采用。用户拒绝练习时，不应因为检索到了卡片就继续带练习。

方法卡不是完整的治疗方案。仓库也没有打包真实咨询原文、用户记忆或书籍全文。第三方出版资料只提供来源清单，其版权不包含在代码的 MIT 许可中。导入方法见 [知识库说明](../knowledge/README.md)。

## 模型由开发者选择

回复、安全判断和记忆提取按角色配置，可以使用同一个模型，也可以分别选择。仓库不预填部署专用的模型 ID，开发者填写自己的服务端点、凭证和模型名。

目前聊天适配层使用 OpenAI 兼容的 Chat Completions 接口，模型需要满足本项目的结构化输出要求。其他协议需要接适配器。历史模式标识中保留的 `claude`、`claude_coach` 不限制模型品牌。

Embedding 的模型和端点也可配置，但当前向量存储要求输出 1024 维。更换 embedding 模型后，需要重建方法卡和事件向量；即便维度相同，也不能把不同模型的向量混在一起比较。

模型能返回文本，只是接入的开始。还要验证格式、截断处理、记忆原句核对和安全行为。这里没有承诺每个兼容接口背后的模型都有相同表现。

## 第一次试用，先看一轮能否完整结束

按 [快速开始](../README.md#快速开始) 克隆仓库，安装依赖，准备空数据库并填写配置。初始化表结构，创建测试账号，然后启动一个 worker 的服务。

可以用这样的虚构输入开始：「我明天有三件事要做，想先把顺序理一下。」先检查认证和完成事件，再查看自己的历史接口是否保存了这轮对话。切换模式后复用同一个虚构场景，比较的是回应方式，不是预设某个模式一定更好。

想检查跨会话记忆时，给后台任务留出完成时间，再验证记忆是否写入和检索；不要把一次没提起旧信息直接判断成存储失败。它也可能是模型选择了不使用该信息。

没有模型凭证也可以先阅读提示词、运行模型替身测试。数据库集成测试需要单独配置本机测试数据库，否则会明确跳过。已有验证及未验证项都记录在 [验证说明](VALIDATION.md) 中。

## 当前还需要开发者补什么

这是后端项目，不是安装后就能面向所有用户开放的完整产品。前端交互、账号体系、访问频率限制和运维监控需要自行集成。当前实现要求单进程、单 worker，请求受全局锁协调；它适合开发评估和小规模使用，没有高并发能力的验证结论。后台记忆任务也不是持久任务队列，进程退出可能丢失未完成的提取工作。

自行部署也不等于完全离线。消息及相关上下文可能发送给配置的模型和 embedding 服务，部署者需要向使用者说明这些数据流。

项目没有经过临床效果验证，不提供诊断或治疗承诺，也不能作为紧急救助渠道。英文提示词目前是对照译文，不代表英语服务或各地区安全话术已经验证完毕。

## 欢迎一起改进

最有用的反馈通常很具体：某条安装命令缺了前提，一个虚构案例让模型重复追问，或一处译文改变了原意。可以开 Issue 说明，也可以 Fork 后提交 PR，由维护者审核合并。

如果暂时不想改代码，跑一遍快速开始、校对文档或补一个虚构回归案例，也能帮助下一个使用者。请不要把真实聊天、用户记忆、密钥或数据库导出贴到公开讨论中。
